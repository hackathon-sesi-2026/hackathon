# Contexto do projeto

Leia nesta ordem e pare assim que tiver o que precisa.

| Arquivo | Responde | Quando abrir |
|---|---|---|
| `produto.md` | O que é o Selo Saúde, o alvo do hackathon, persona, superfícies, regras, vocabulário, decisões em aberto | Sempre. Já é carregado pelo `CLAUDE.md` |

## Materiais do SESI

Em `materiais-sesi/`. São a fonte bruta, convertida dos originais. O essencial já está resumido nos arquivos acima; abra um destes só para conferir um detalhe ou citar a fonte.

| Arquivo | Conteúdo |
|---|---|
| `abertura.md` | Slides de abertura: números do programa, pergunta-desafio, barreiras, escopo, o que o SESI espera receber |
| `regulamento.md` | Regras, cronograma e critérios de avaliação (seção 8) |
| `desafio/gestao-de-retorno.md` | Ficha de monitoramento da enfermagem |
| `desafio/plano-de-cuidados.md` | O plano que o trabalhador recebe hoje |
| `desafio/gestao-do-cuidado.md` | Ficha clínica de coordenação. Dado sensível, não entra no produto |
| `desafio/fluxo-do-processo.png` | Mapa da APS |
| `workshops/1-validacao-problema-proposta-valor.md` | Validação de problema e proposta de valor |
| `workshops/2-modelagem-prototipagem.md` | Modelagem e prototipagem |
| `workshops/3-treinamento-pitch.md` | Estrutura do pitch |
| `viabilidade-financeira.md` | Como montar o argumento de viabilidade |

Não estão no repositório: o documento do desafio (`.docx`), a planilha de dados fictícios (`.xlsx`) e as decisões do time registradas no Notion. O que importa deles está em `analise-desafio.md` e `produto.md`.

## Como manter

- Decisão de produto nova entra em `produto.md`, na seção certa, e sai de "Decisões em aberto" quando for tomada.
- Os arquivos de pesquisa e análise descrevem o mundo e a evidência; o estado do produto muda rápido, então a referência para "o que já existe" é o código.
- A identidade visual de referência está em `referencias/referencia-visual.png`.
